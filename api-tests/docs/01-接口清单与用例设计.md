## 2. 用例设计矩阵

设计方法：等价类划分 + 边界值 + 场景法（多参数组合）+ 错误推测（针对代码复杂度高的分支）。

### 2.1 功能用例（TS = 必须全绿）

| 编号 | 用例 | 断言要点 |
|---|---|---|
| TS-01 | 四个页面路由可达 | 200 + `text/html` |
| TS-02 | `/api/images` 默认分页 | `total` 覆盖 detection + CIT-only |
| TS-03 | 正常分页第 2 页 | 只返回剩余 1 条，`total` 不变 |
| TS-04 | UUID 子串搜索（命中/未命中） | 等价类：有结果 / 无结果 |
| TS-05 | `/api/image/<uuid>` 四源聚合 | pose/detection/cit/dino 均非空 |
| TS-06 | 关键点置信度过滤（业务规则 ≤0.3 不返回） | 断言最小值 > 0.3，且总数 133 |
| TS-07 | `/api/stats` 统计口径 | 分类计数之和 = `total_images`；高置信关键点 = 133×图数 |
| TS-08 | 朝代选项来自 CSV | 验证 CSV 数据源生效（守护 D02） |
| TS-09 | `/api/filter` 单条件 + 多条件 AND | 多条件组合应取交集 |
| TS-10 | 两个列表接口口径一致 | `/api/human_stats.total` == `/api/human_annotations.total` |
| TS-11 | 人工标注详情 404 语义 | 不存在返回 404 + `error` 字段（与 D05 对比） |
| TS-12 | `/api/shinu52` 固定 52 条 | 契约稳定性 |
| TS-13 | `/api/mingqing_ids` 返回列表 | 纯 ASCII 数据不受 D11 影响 |
| TS-14 | 下载空结果返回 400 | 不应生成空 ZIP |

### 2.2 边界用例（TD-02~04）

| 编号 | 输入 | 期望 | 实际 | 结论 |
|---|---|---|---|---|
| TD-02 | `page=0` | 返回第一页 或 400 | 200 + 空列表（`total` 仍为 3） | **D06 缺陷** |
| TD-03 | `per_page=-1` | 返回全量 或 400 | 200 + 少最后 1 条 | **D06 缺陷** |
| TD-04 | `per_page=1e8` | 400 或截断到上限 | 200 + 全量返回 | **D07 缺陷** |

根因（同一处代码）：`app.py` 第 676-711 行

```python
page = request.args.get('page', 1, type=int)        # 未校验 >= 1
per_page = request.args.get('per_page', 200, type=int)  # 未校验上限与正负
start = (page - 1) * per_page
end = start + per_page
return jsonify({'items': all_items_list[start:end], 'total': total})
```

Python 切片对越界参数不报错，反而按负索引静默取到"看起来正常"的结果，是典型的**静默错误**：前端不报错、用户无感知地拿到错数据。

### 2.3 异常与安全用例（TD-01、待补 D03/D04）

| 编号 | 场景 | 说明 |
|---|---|---|
| TD-01 | 不存在的 uuid 请求 `/api/image/<uuid>` | 期望 404，实际 200 → **D05** |
| 待补 TD-10 | `/images/..%2F..%2Fetc%2Fpasswd` | 路径穿越；当前实现是把 filename 拼到云端 URL，可直接改查询串（D03） |
| 待补 TD-11 | `filename` 含 `&bucket=other` | 参数注入，越权读取其他 bucket 对象（D03） |
| 待补 TD-12 | 无凭据调用 `/api/download` | 系统无任何鉴权，可批量下载全量标注数据（D15） |
| 待补 TD-13 | 云端返回 500/超时 | 服务端应降级并返回明确错误，而非空 body（D09） |

### 2.4 数据一致性用例

| 编号 | 断言 | 说明 |
|---|---|---|
| TS-08 | CSV 中的朝代能出现在 `/api/filter_options` | 数据源链路完整性 |
| TS-10 | 列表接口与统计接口计数一致 | 同源不同接口的口径对齐 |
| TD-09 | `/api/images_count.total` == `/api/images.total` | 因 D11 暂被阻塞，修复后可转为冒烟 |
| 待补 | `/api/download` 的 ZIP 内图片数 == 筛选结果数 | 跳过云端下载失败的图时需在 `annotations.json` 或响应头中体现 |

## 3. 测试数据策略

| 方案 | 数据量 | 启动耗时 | 结论 |
|---|---|---|---|
| 直接使用真实数据 | 549 MB（`pose_results_all.json` 366 MB） | 分钟级、内存数 GB | 不可用于 CI |
| **seed 数据集（采用）** | 3 条图片记录 + 133 关键点/人 + 4 个 CSV | < 2 s | CI 友好、用例可精确断言 |
| 运行时抓取真实数据 | — | 依赖内网/云端 | 不稳定 |

关键动作：给 SUT 增加 `GUOHUA_DATA_DIR` / `GUOHUA_CSV_DIR` / `GUOHUA_PORT` 三个环境变量入口，使同一份业务代码既能跑真实数据，也能跑测试数据。**这是"可测性设计"而非改需求。**

## 4. 覆盖缺口（如实记录）

- 云端依赖接口（`/api/thumb`、`/api/cloud_url`、`/images/<path>`、`/api/scroll`）未接入 `requests-mock`，4 个路由仅做静态分析。
- 无性能/容量用例：`/api/scroll` 的瓦片拼接是 N 次串行 HTTP，是天然的 P95 长尾点，待接入 Locust。
- 无前端 E2E：4 个页面的渲染错误（如本次搬运模板缺失导致的 500）目前靠人工发现，后续应由 Playwright 覆盖。
